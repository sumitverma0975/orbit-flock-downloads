# Delhi Drive · Unreal Engine 5.5

An Android driving game project set in two 1.2 km-radius districts around Connaught Place, Delhi, and central Chandigarh. Choose a car, a city and a difficulty, then enter Driving School, Career or Open World Tour. This is a source milestone. It has not been compiled, cooked, installed or played in Unreal on this host. See [verification](VALIDATION.md).

[View all 12 prepared models in the offline Blender garage preview](Docs/vehicle-garage-preview.png).

## Driving

- Six lessons cover stopping, steering, speed control, parking, passenger comfort and a final driving test.
- Twelve original career challenges use timed routes, repeated delivery stops, fuel budgets, smoothness limits and final parking bays. Stars and score unlock more challenges and cars. The challenge layouts and assets were authored for Delhi Drive.
- Tour has no timer or fuel limit. The local street map follows the driver and displays the road name when available.
- The garage has twelve cars. Three use attributed BMW 320i, Mercedes-Benz G-Class and Mercedes-AMG GT models. Nine are original performance or luxury designs. Each has its own dimensions, weight, drivetrain and handling values. The native pawn simulates four suspension and tire contacts against a Chaos rigid body. It does not require a hand-rigged vehicle Blueprint. Imported car models have integrated static wheels. Their handling values are game tuning.
- Touch controls include a steering wheel, proportional gas and brake, handbrake, reverse, manual or automatic gears, four cameras and vehicle recovery. In the garage, select the session and city at the top of the screen. Credits are available in the garage. Keyboard controls are in [DrivePlayerController.cpp](Source/DelhiDrive/DrivePlayerController.cpp).

## Geography and graphics

The Delhi extract has 862 road parts and 1,299 mapped building outlines. Chandigarh has 677 road parts and 1,088 outlines. Each city generates a connected drive along its road network. The levels use different objectives and lengths along a shared city itinerary. Navigation and left-hand traffic respect mapped one-way directions. Ground elevation is flat. The extracts omit some road and building types and cover a district in each city. They are independent maps, with city selection in the garage.

The renderer uses mobile forward shading, daylight image-based lighting, a directional light, photographed asphalt and plaster, distance haze, facade materials, tiled building meshes and instanced street props. Building outlines and tagged roads come from OpenStreetMap. Unmapped heights, traffic, trees, potholes and other simulated details are illustrative. Frame rate, visual fidelity and real-device memory use require an Android build and profiling.

## Build on an Unreal Android workstation

Install Unreal Engine 5.5 with Android platform support, a working desktop C++ compiler for the editor target, and the Android SDK, NDK and JDK supported by that exact engine release. Use Python 3.10 or later for the host tools (Python 3.12 was used for validation). The source archive includes the prepared car meshes, surface textures, daylight panorama, district maps and geometry. Asset preparation does not require an online map service or Blender during a normal build.

Linux or macOS:

```sh
export UE_ROOT="/absolute/path/to/UE_5.5"
bash Tools/build_apk.sh
```

Windows, from Command Prompt:

```bat
set "UE_ROOT=C:\Program Files\Epic Games\UE_5.5"
Tools\build_apk.bat
```

The helper checks source data, runs Turnkey, compiles DelhiDriveEditor, imports assets, generates both city maps, and asks Unreal Automation Tool for an ARM64 ASTC Shipping package. The on-device PBR materials and maps are generated by the editor. Editor import or native compilation issues may still surface on the first build. Configure Android signing locally in Unreal for release distribution. Keep private keys and passwords outside source control.

The verifier requires a valid APK signature, an ARM64 Unreal library and cooked game data. It checks that the combined deliverable stays at or below **3,000,000,000 bytes**. The source ZIP size is independent of the installed or downloadable game size. See [the build attempt](Docs/UE5-build-attempt.log).

## Build and download through GitHub Actions

Pushing a tag named `delhi-drive-ue5-android-*` on a revision of this project starts **Package Delhi Drive for Android**. The runner needs Python 3, Unreal 5.5 with Android platform support, and a configured Android SDK/NDK. Use the repository variable `DELHIDRIVE_ANDROID_RUNNER` to select a connected Windows, Linux or macOS runner by label. The default is GitHub's `windows-2022` image, which needs an accessible engine installation. Set `DELHIDRIVE_UE_ROOT` to the engine directory, or supply `UE_ROOT` on the runner. Windows also checks the standard Epic Games install location.

A successful run uploads the verified APK, its SHA-256 and its verification report as the **DelhiDrive-Android** workflow artifact. For APKs below GitHub Releases’ 2 GiB per-file limit, it also publishes a prerelease with a direct APK link in the run summary. Larger APKs that meet the game's 3 GB limit remain available through the workflow artifact. If compilation, cooking or verification fails, the run ends without publishing a download.
